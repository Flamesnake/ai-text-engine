# `story_evaluate` 公开校准原则

本文件只记录可公开复用的评估原则。用于校准的个人作品、剧情内容、节点 id、路线和逐作品指标保留在本地，不随源码仓库或未来 npm 包分发。

## 指标边界

- 不因作品没有谜题、人物关系、富文本或手动声画效果而告警；
- 单选项比例、条件选择比例和机制数量只描述结构，不能单独代表质量；
- 重复导航、重复结果和未回收机制以带证据的候选问题报告，不输出总分；
- walk 的结局可达证明与全状态覆盖诊断分开，不能为了消除截断而机械线性化作品；
- 自动评估不能替代谜题公平性、文案提示、演出节奏和真人试玩。

## 选择质量与机制回收

- “重复结果”要求同一节点内目标、条件和效果完全相同；它可能是有意的语气选择，因此只提示作者检查是否需要结构化后果；
- “未回收证据”不等于没有叙事价值，纯阅读线索仍可能帮助真人推理；它主要用于发现遗漏的推论、条件或结局门控；
- 零选项状态如果仍可确认推论或解开谜题，不应被误报为软锁；已经找到的软锁需要运行时重放确认。

## 声画契约

- 没有手动 `sfx`/`fx` 的作品不会被机械要求补效果；
- 全节点重复音效、连续低频氛围、重复系统反馈、长正文强动画和高强度效果仅作为审查候选；
- `sfx`、`fx.intensity` 与 `fx.speed` 的非法输入由严格 schema 在写入时拒绝；
- 语义是否匹配场景最终仍由真实试玩判断。

## 富文本最小纵向校准

- 公开 `_rich-text-showcase` 验证受控样式、条件遮挡、证据解锁、纯文本回退和单 HTML 导出；
- 条件未满足时真实文本不进入 DOM，只存在可访问说明与确定性占位符；
- handler 拒绝未知 style 与任意 `html` 字段；静态校验检查揭示条件引用与文本插值；
- `story_evaluate.presentation` 只统计片段节点、片段数、条件片段与样式分布；
- 以短语义片段代替逐字符乱码，减少无意义的工具输入和 token 消耗。

## 私有校准要求

每次调整启发式规则时，至少使用两部机制重心不同的本地作品验证误报与漏报。公开提交只记录可复用结论；私有作品和逐作品结果不得加入 Git 暂存区、发布 tarball 或 CI fixture。
