# TaleSpindle 第一轮盲测评分表

> 本文件只给评估者使用，不要发送给生成 Agent。否则会把“能否主动做出合理设计”变成照表填字段。

## 评估流程

1. 保存生成 Agent 的最终回复、`story.json`、导出 HTML 和校验结果。
2. 确认它只收到对应盲测题，没有收到本评分表或额外实现提示。
3. 静态检查剧情模型与 `story_validate`。
4. 至少实际游玩两条路线：一条真相/深层结局，一条错误或普通结局。
5. 音效开启游玩一次；如系统允许，再用“减弱动态效果”确认可访问性回退。
6. 按下表评分，并把问题归因到 Agent、skill、MCP、运行时或引擎表达力。

## 一票否决项

出现任一项时，本题最高 59 分：

- 无法导出或 HTML 无法开始游戏；
- `validatePass` 为 false；
- 登记结局存在不可达项；
- 真相/深层结局依赖游戏内没有提供的信息；
- 关键机制只有顶部隐蔽入口，正文行动区没有可发现路径；
- 存在无法退出的非结局死路；
- 用强烈、持续动画导致大部分正文难以阅读。

## 总分（100）

### 1. 需求理解与叙事设计 · 20 分

- 0–5：场景、玩家身份和核心冲突符合题目。
- 0–5：真相/人物动机在创作前后自洽，误导有反证。
- 0–5：三个结局有因果和情感差异，不是同一结尾换标题。
- 0–5：篇幅与节奏接近 15–20 分钟，没有大量灌水节点。

### 2. 互动系统整合 · 25 分

- 0–5：调查/探索行动不只是纯分支，能改变玩家掌握的信息。
- 0–5：人物关系变化有记忆原因，并影响证词、秘密、行动或结局。
- 0–5：谜题答案可从游戏内推出，入口醒目，允许返回搜证，提示递进。
- 0–5：证据与推论结构正确，推论确实解锁后续内容。
- 0–5：各机制彼此作用，而不是三个互不相关的小演示。

### 3. 玩家引导与可发现性 · 15 分

- 0–4：多行动中心、谜题现场和结案阶段有清楚的当前目标。
- 0–4：新证据、推理板和关键解锁有可理解反馈。
- 0–4：选项文案说明行动与风险，坏结局不是无预警误触。
- 0–3：没有大量只有一个选项的过场；必要单选过场简短且有叙事价值。

### 4. 氛围与特效叙事 · 25 分

此项评估“为什么在这里用”，不是统计用了多少种。

- 0–5 语义匹配：音效/动画与事件一致。例如心跳用于迫近危险，`unstable` 用于坏灯，`glitch` 用于信息或系统失真；不能因为题材是恐怖/科幻就全程套用。
- 0–5 克制与可读性：普通阅读节点多数保持稳定；持续闪烁、抖动和毛刺不会覆盖长篇正文；强烈效果只用于短节点或高潮。
- 0–5 强度与速度：参数有判断。轻微不安通常使用低强度，突发事件才提高；没有大量默认满强度或极端频率。
- 0–5 氛围曲线：效果随剧情阶段变化，能形成铺垫、升级、高潮、余韵，而非从头到尾同一种效果。
- 0–5 声画协同：声音和动画互相补充，不机械重复；自动点击、翻页、成就和结局音效没有被无意义地手动滥用。

#### 特效分数参考

- 21–25：少而准，去掉任何一个都会损害叙事节奏。
- 16–20：整体合理，有一两处偏多或偏保守。
- 10–15：使用了特效，但更像题材预设或功能展示。
- 1–9：严重滥用、语义错配，或明显影响阅读。
- 0：完全未用。若作品极其克制但题目明确要求氛围变化，仍记 0；“不用”也是未展示该能力。

### 5. 工程与 Agent 自检 · 15 分

- 0–4：`story_validate` 结构通过、所有结局可达。
- 0–3：`experienceWarnings` 为零，或 Agent 对无法消除的警告给出合理说明。
- 0–3：Agent 使用 MCP 完成创作，没有绕过工具直接篡改项目数据。
- 0–3：Agent 主动检查分支图、路径或进行实际游玩验收。
- 0–2：最终交付路径明确，成品可直接打开。

## 归因标签

每个主要问题选择一个首要归因：

- `AGENT-JUDGMENT`：能力存在、skill 已说明，但 Agent 选择不当，例如滥用 `glitch`。
- `SKILL-GUIDANCE`：多个 Agent 重复犯同类错误，说明 skill 缺少创作原则或示例。
- `MCP-AFFORDANCE`：工具字段/描述让 Agent 难以发现或正确表达意图。
- `RUNTIME-UX`：数据正确，但玩家界面没有传达操作方式或反馈。
- `ENGINE-LIMIT`：设计合理，却无法用现有数据模型表达。
- `PROMPT-AMBIGUITY`：题目本身导致多种同样合理的理解。

## 三题汇总结论

- 单题及格：总分 ≥ 75，且“系统整合”≥ 16、“氛围与特效”≥ 16，无一票否决。
- 引擎阶段通过：三题至少两题及格，三题均可导出且所有结局可达。
- 若三题同类问题出现两次以上，优先视为系统性问题，应更新 skill、MCP 或运行时，而不是只修改样例。
