# 叙事文本与节点连续性

TaleSpindle 不尝试用“AI 检测器”给文风打分。此类判断不稳定，也容易把题材习惯误判成缺陷。引擎提供可验证的结构支持，作者 Skill 负责编辑流程。

## `choice.response`

选项可带短 `response`。玩家点击后，它显示在目标节点正文之前，并随存档保存：

```json
{
  "label": "承认自己看见了灯塔",
  "response": "她没有追问。指尖却从杯沿挪开了。",
  "target": "shared_evening"
}
```

它适合不同态度或动作汇入同一公共节点的情况。`response` 写即时反馈，目标节点写共同的新发展；二者不应重复。纯导航通常不需要承接文本。

## 评估器能检查什么

`story_evaluate` 会报告：

- 多个选项汇入同一目标、但没有完整 `response` 的高风险边；
- 至少三处完全相同的节点开头，作为模板化写法的人工复核候选；
- world/phase 被写入却没有外观、条件或可见文本用途；
- world 与 phase 同时声明基础声景时的覆盖风险。

这些都是候选问题，不是总分，也不是文风判决。人物语气、段落节奏、因果连贯仍需真实阅读。

## 推荐验收单位

不要孤立审查一个节点。最小验收单位应是：

`上个节点末段 + 选项 + response + 下个节点首段`

重点审查汇流、跨场景、跨世界、关系变化和结局入口。完整工作流见 `skill/references/prose-and-transitions.md`。

## 低成本修订工具

- `story_review_transitions` 按页返回紧凑转场阅读单位，默认 20 条、最多 50 条；
- `story_get_node` 只读取一个节点和指向它的选择；
- `story_patch_choice` 只修改指定选项，可用 `expectedLabel` / `expectedTarget` 防止过期索引误改。

`onlyRisks: true` 只用于先找断链、自环和汇流缺承接等确定性风险。完整连贯性审查仍应分页阅读全部关键边，因为引擎不能可靠判断人物语气和因果是否自然。
