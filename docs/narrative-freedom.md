# 文字冒险表达自由度设计原则

本文定义 TaleSpindle 应当增加什么自由度、拒绝什么自由度，以及 2D/3D 场景能力进入核心前必须满足的条件。

## 核心判断

单文件 HTML 是交付容器，不是产品范围。浏览器能够承载复杂网页、Canvas、WebGL 乃至完整 3D 游戏，但 TaleSpindle 的目标不是覆盖浏览器的全部能力，而是让 Agent 稳定创作、校验和导出更好的文字冒险。

> 所有表现、空间和技术能力，都必须为阅读、选择、调查、人物关系、推理、解谜、氛围或叙事结构服务。

项目优先增加**表达自由度**，不直接开放**任意实现自由度**：Agent 描述叙事意图和结构化参数，引擎负责安全、可访问、可测试的实现。

## 自由度的四层模型

### 1. 文本表达层

用于改变玩家如何阅读和理解文字：

- 强调、斜体、血字、耳语、手写、终端文字；
- 遮挡、删除、可恢复乱码和条件揭示；
- 逐字显现、停顿、短促故障与克制的阅读动画；
- 纯文本回退、屏幕阅读器语义和减弱动态效果。

这一层优先级最高，因为它直接增强文字本身，不要求额外素材，也最符合单文件与低 token 成本目标。

### 2. 世界与媒介层

用于让界面成为故事的一部分：

- 白天、夜晚、断电、警报、表世界、里世界等受控世界状态；
- 新闻站、论坛、博客、邮件、档案库、广播台等拟态外壳；
- 世界状态改变正文、可见行动、导航、声景和少量关键演出；
- 单周目、跨周目和临时界面状态严格分离。

视觉变化必须对应逻辑状态。不能把关键行动藏在纯 CSS 中，也不能依赖玩家查看源码或真实浏览器历史。

#### 受控舞台调度

对话、对质和结局需要的“舞台感”优先通过短枚举表达：程序化布景、语义灯光、有限镜头、最多三人的站位/姿态/焦点，以及短促入场。舞台沿节点历史持续，Agent 只发送变化项；这比逐节点生成布局和动画代码更稳定，也更节省 token。

产品目标不是复刻任意代码舞台剧，而是以受控配置获得约 60–70% 的感知收益。时间轴、骨骼动画、口型、外部视频和任意 CSS/JavaScript 暂不进入核心。舞台只改变表达，不决定选项、证据或结局；正文始终提供完整语义回退。

### 3. 受控空间调查层

空间不是独立小游戏，而是文字调查的另一种索引方式。候选组件包括：

- 房间、船舱、楼层或区域平面图；
- 可键盘操作、可列出文本替代的调查热点；
- 证物近观、局部放大、翻面和前后状态对比；
- 时间线、人物关系图与证据位置图；
- 2D 分层、视差、雾、雨、灯光和有限镜头运动；
- 由 `world`、`phase`、证据或推论控制的热点显隐与场景变化。

建议的数据方向：

```jsonc
{
  "surface": "scene",
  "scene": "yacht_deck",
  "variant": "storm_blackout",
  "camera": "slow_push",
  "hotspots": [
    { "id": "lifeboat", "label": "检查救生艇吊架", "target": "inspect_lifeboat" },
    { "id": "wake", "label": "观察船尾航迹", "target": "inspect_wake" }
  ]
}
```

热点最终仍转化为剧情节点、选项、证据或状态变化，因此 validate、walk、存档和运行时验收仍能理解它们。

### 4. 可选 3D 调查表面

3D 只作为受控空间层的一种渲染方式，不成为新的剧情逻辑系统。首个实验最多支持：

- 固定摄像机或少量预设观察角度；
- 有限几何体、灯光、雾、材质和嵌入式轻量模型；
- 点击/键盘选择热点，进入现有调查节点；
- 状态驱动的物体显隐、灯光和天气变化；
- 无 WebGL 时自动退化为平面图或热点列表。

首个实验不支持自由行走、物理、碰撞、角色控制、战斗、开放世界、任意 shader、Agent 编写 WebGL 代码或完整 3D 关卡编辑。

## 功能进入核心的判定门槛

新增能力至少应满足以下多数条件：

1. 明确增强阅读、选择、调查、关系、推理、解谜或氛围中的一项；
2. Agent 能用少量结构化字段表达，不需要生成 CSS/JavaScript；
3. 关键逻辑可被 schema、validate、walk 或运行时测试理解；
4. 没有该表现层时仍存在可玩的文本回退；
5. 导出仍可离线、自包含，并具有可接受的体积和启动时间；
6. 至少两个不同题材能复用，而非只服务一个展示样例；
7. 盲测显示它解决了真实体验问题，而非单纯增加视觉炫技；
8. 配置和素材不会显著增加 Agent 的重复调用与 token 浪费。

任何能力只要破坏关键推理的可验证性、迫使 Agent 重复描述大量布局，或让玩家必须操作视觉界面才能获得唯一关键事实，就不应直接进入核心。

## Token、素材与导出成本

- 使用场景模板、短枚举和差异覆盖，不让 Agent 逐节点重复布局、颜色和动画；
- 热点只保存 id、标签、目标和条件，叙事正文继续复用节点；
- 2D/3D 素材通过资源清单管理，二进制内容不进入 MCP 对话正文；
- 模型、纹理和音频设置单文件体积预算，导出器报告各类资源占比；
- `story_evaluate` 需要报告重复场景声明、无叙事作用热点、不可访问热点和资源预算；
- 先用程序化图形与共享素材验证玩法，再决定是否支持用户自带资产。

## 3D 实验的前置条件

只有同时满足以下条件，才启动小型 3D 原型：

- 富文本、声景、世界状态和拟态网页已经稳定；
- 2D 平面图/热点调查组件已在至少两部作品中验证有效；
- 盲测或玩家反馈反复出现“空间关系难以仅靠文字和平面表达”的证据；
- 能复用现有节点、条件、证据、存档与 walk，不建立第二套剧情系统；
- 可以提供无 WebGL、键盘和屏幕阅读器回退；
- 原型的创作调用量、导出体积和运行性能有明确预算。

建议首个原型是一个单场景、固定视角的“游艇甲板调查”：玩家通过少量热点理解救生艇、航迹、灯塔和舱门之间的空间关系，所有发现仍进入现有证据与推论系统。若 3D 相比平面图没有显著改善推理体验，就停止扩展。

## 永久架构边界

- 剧情状态只有一个真相源，表现层不得私藏决定结局的状态；
- 任意表现表面最终映射到现有行动、节点和效果；
- Agent 不注入任意 HTML、CSS、JavaScript、shader 或远程脚本；
- 自包含 HTML 是默认交付，外部资源只能作为未来明确选择，而非隐式依赖；
- 文字冒险体验优先于技术展示，复杂度必须由玩家获得的体验价值偿还。
