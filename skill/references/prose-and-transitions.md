# 文风与节点承接

用于正文较多、人物对话重要、用户指出“AI 味”，或多个选择汇入同一节点的作品。目标不是伪装作者身份，而是让文本具体、人物可辨、行动有连续后果。

## 先做一份全局声纹表

写节点前用不超过 5 行记录：

1. 叙述视角与距离；
2. 句子节奏（长短、停顿、是否允许残句）；
3. 反复出现的具体物件与感官范围；
4. 每个主要人物的两个说话习惯和一个绝不会使用的表达；
5. 本作最容易滥用的两种修辞。

这份表只写一次，不要在每次 `story_upsert_node` 中重复。人物不能都说完整、漂亮、概括主题的话；允许打断、答非所问、口误、回避和不均匀节奏，但每种习惯必须服务于人物或场景。

## 用连续性卡写节点

每个节点动笔前只记四项：

- 入口：玩家刚刚做了什么；
- 回声：环境或人物最先发生的可观察反应；
- 变化：这一节点带来什么新信息、压力或关系位移；
- 出口：玩家离开时，局面与进入时有什么不同。

目标节点的第一段必须假定选项已经发生。不要重新介绍场景，也不要用“你决定……”“一切似乎……”把动作抽象复述一遍。

## 选择与 response

有意义的选择至少满足一项：目标不同、产生结构化效果/记忆，或拥有独立的 `response`。多个不同选项汇入同一目标节点时，为每条路径写 `response`：

```jsonc
{
  "label": "把照片还给她",
  "response": "她先接住照片的右下角，等你松手，才把另一只手合上。",
  "target": "after_photo",
  "effects": { "remember": ["returned_photo_gently"] }
}
```

`response` 只负责即时动作与反应，通常一两句；下一节点负责共同发生的新事件。不要在两处重复同一信息。纯导航（“返回大厅”）不必机械填写。

## 去模板化编辑

逐场执行，不做全局禁词替换：

1. 删除已经由动作或对白表达过的情绪总结；
2. 把“悲伤、紧张、诡异、温柔”等抽象判断换成能被看见或听见的细节；
3. 检查连续的整齐三项、对称句、段尾主题总结，它们若不属于人物声纹就拆开；
4. 搜索反复出现的“不是 X，而是 Y”“像 X，又像 Y”、省略号、破折号和括号式解释，只保留真正准确的一处；
5. 删除可移植到任何作品的天气、光线、呼吸和心跳描写；保留与地点、人物习惯或线索有关的细节；
6. 允许少量短句、残句和沉默，不把每段都润色成同一种文学腔。

不要只提示模型“降低 AI 味”。应指出具体场景目标、人物声纹和要删除的重复修辞。

## 逐边验收

把每条关键边按下面顺序连读：

`选项 label → response（若有）→ 目标节点第一段`

检查：代词是否有明确指向；人物位置和手中物件是否连续；目标节点是否回应了选择；时间是否无故跳跃；共同节点是否错误假定了某一条分支。优先检查汇流边、关系选择、进入结局前的边和跨 world/phase 的边。

先使用 `story_review_transitions { title, onlyRisks: true, limit: 50 }` 取得确定性风险，再使用 `onlyRisks:false` 分页连读其余关键边；每项已经包含源节点末段、选项、`response` 和目标首段。不要为了检查衔接反复调用 `story_get`。

`response_repeats_target_opening` 表示 response 与目标节点第一句完整重复或高度重合。这是保守的短文本相似候选，不是文学质量判决。不要简单删除 response：应让它保留玩家动作的即时后果，再让目标正文从新的状态继续。例如不要连续显示“标本展厅只剩一盏灯／标本展厅的灯只剩一盏”，可以把 response 改为“你推开防火门，最后一根灯管闪了两次”，目标节点再从人物或物件的变化继续。

修订时根据返回的 `sourceNodeId`、`choiceIndex`、`label` 和 `targetNodeId` 调用：

```jsonc
{
  "title": "作品名",
  "nodeId": "source_node",
  "choiceIndex": 1,
  "expectedLabel": "保持沉默",
  "expectedTarget": "shared_scene",
  "patch": { "response": "她等了两秒，把你没说出口的话也收进沉默里。" }
}
```

旧值断言冲突时重新读取该节点，不要改用过期索引强行覆盖。`story_evaluate` 的 `CONVERGING_CHOICES_WITHOUT_RESPONSE`、`RESPONSE_REPEATS_TARGET_OPENING` 和审查工具的 `risks` 只定位确定性结构风险，不能代替人工连读。
