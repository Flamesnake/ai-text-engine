# Walk 路径探索与性能诊断

仅在作品包含开放 hub、可重复探索、推论、谜题，或 `story_walk` 接近/超过状态预算时读取。

## 机制

`story_walk` 会把当前节点、已访问节点、证据、文档、推论、关系、记忆、秘密和谜题状态纳入搜索状态。开放 hub 可以使用，但“多个场景任意排列 × 重复访问仍改变状态 × 过早可确认推论”会产生组合爆炸。

walker 会探索玩家暂不确认或确认当前可用推论的状态，也会探索当前节点可解决的谜题状态。推论越早成立，后续节点越多，其组合乘数越大。

## 先诊断，再改结构

```jsonc
{
  "title": "作品名",
  "diagnostics": true,
  "topNodes": 10,
  "maxStates": 100000
}
```

`story_walk` 把两个不同问题分开报告：

- `budget.used / limit / utilization`：预算占用；
- `hotNodes`：访问次数最高的节点，优先检查 hub、回廊、可重复内容和过早推理点；
- `reachability.allEndingsProven`：是否已经为全部登记结局找到至少一条路径；
- `reachability.witnesses`：可由 `Game` 或运行时验收器重放的选择、推论和谜题动作；
- `reachability.unprovenEndings`：预算内尚未找到见证的结局；它表示“尚未证明”，不等于数学上的不可达；
- `failures.witnesses`：已经实际找到的失败路线；`soft_lock` 表示节点存在选项但在该状态下全部被锁且没有可用推理/谜题行动，`invalid_terminal` 表示无选项也无结局；
- `failures.complete`：失败搜索是否覆盖完整；为 `false` 时“当前列表为空”不能解释为作品没有软锁；
- `coverage.complete / reasons`：全状态覆盖是否完成，以及是状态预算、深度、节点访问还是推论组合限制导致不完整；
- `truncated`：兼容字段，只表示主探索耗尽 `maxStates`；
- `warnings`：循环、推论组合截断、深度和近预算警告。

主探索不完整时，walker 会对缺失结局追加目标导向搜索；`witnessMaxStates` 是每个缺失结局的预算，默认 25,000。它只调整选择顺序，不依据静态距离剪枝，因此不会因条件门控跳过必要调查。必要时可临时提高 `maxStates` 或 `witnessMaxStates` 做定位，但不要把提高上限当作结构修复。也可调整 `maxDepth`、`maxNodeVisits`、`maxDeductionVariants`。

## 健康度

- `< 10,000`：通常轻量；
- `10,000–50,000`：检查循环与无意义排列；
- 预算使用率 `>= 80%`：高风险，即使未截断也应查看热点；
- `reachability.allEndingsProven: false`：结局可达性验收不通过；先检查条件语义与见证搜索热点；
- `failures.witnesses` 非空：逐条重放并修复，或明确记录这是有意的陷阱结局设计；通常有意失败应写成正式 `bad` 结局，而不是让界面无响应；
- `coverage.complete: false`：覆盖风险，需记录原因并检查热点，但不能单凭此项要求删除有价值的自由调查；
- 全部结局有见证也不证明没有死路、软锁或交互问题，仍需运行时验收。

## 收敛顺序

1. 一次性证据、秘密、记忆和内容行动应去重；
2. 重复进入节点不要持续改变状态；
3. 内容完成后切换为简短复查状态或隐藏已耗尽行动；
4. 关系变化不要放在可无条件循环刷取的路径上；
5. 区域入口可重复进入，但用“完成锚”判断区域是否耗尽，避免把玩家锁在区域外；
6. 推论尽量在其确实影响选择的阶段开放，不要过早让所有推论组合贯穿全图；
7. 冷藏舱、密室等局部流程尽量消除无意义回边。

不要为了 walk 把合理的自由调查强行改成纯线性。先依 `hotNodes` 消除重复改变状态的循环和无意义排列。
