# 悬疑、证据与推论设计

仅在作品包含调查、推理、证据组合或结局指控时读取。

## 事实—来源账本

先确定真实事件、人物动机与隐瞒，再设计证据和推论，最后安排场景。真相结局准备陈述的每项具体事实，都必须在玩家判断前有游戏内来源：证据、已揭示秘密、文档或此前确认的推论。结局后的旁白不能倒过来充当前置证据。

推论 `statement` 只能陈述材料确实支持的最小命题。误导应有可发现的反证，关键证据尽量有替代获取路径。

## 结局条件

结局选项同时声称 A 与 B 时，`when` 必须同时要求证明 A 与 B 的成果。复杂真相通常至少整合两条互相独立的 deduction。若人物关系或谜题是核心玩法，至少一条真结局必须要求其产出的秘密、关系门槛、谜题状态或谜题证据。

`requires.anyOf` 的外层数组表示多个都要满足的组，每个内层数组才表示该组任选一条：

```jsonc
// 脚印或目击证词，任选其一
{ "anyOf": [["e_脚印", "e_目击证词"]] }

// 身份组任选一条，并且时间组任选一条
{ "anyOf": [
  ["e_身份证", "e_熟人辨认"],
  ["e_车票时间", "e_监控时间"]
] }
```

## 导出前反向验收

1. 从真结局选项文案提取全部事实和指控，逐项指向前置来源；
2. 查看最短真结局路径，确认没有绕过承诺的核心人物、谜题或调查阶段；
3. 暂时移除任一关键推论，确认真结局不再出现；
4. 修复推理整合类 `experienceWarnings`；确属有意设计时向用户说明理由。
